# Lifecycle operations, version 1

Requires Python 3.11+, Git, OpenSpec **1.15.0**, Beads **1.2.2**. Install OpenSpec with `npm install --global @fission-ai/openspec@1.15.0` in a trusted environment; use the versioned Beads distribution. Never install credentials on public runners.

## Incremental work

1. Read/claim a local Bead (`bd prime`, `bd show`, `bd update ID --claim`). Create/validate an OpenSpec proposal before implementation. `.engineering/work.json` identifies the current stage, scope, change, Bead and base commit. The ID map is `.engineering/roadmap.md`; status lives only in Beads.
2. Run `python3 tools/engineering/lifecycle.py hooks` explicitly. It preserves existing hooks and composes pre-commit/pre-push, replaying push stdin. It keeps other existing hooks active. Re-running is idempotent. To uninstall, restore `core.hooksPath` from the private `previous.json` under the common Git directory. Shared worktrees share the hook directory and tracker; serialize installation.
3. Pre-commit checks the staged diff, added/modified files, database/private/generated content and linkage from the staged work record/proposal. It validates staged OpenSpec artifacts strictly. It does not require a finished journal receipt or final tests on every incremental commit.
4. Stage START, decisions, failures/blockers and completion are private events. Use `event --details PRIVATE_JSON` after configuring `ENGINEERING_OUTBOX` to an external private directory and `ENGINEERING_JOURNAL_ADAPTER` to an explicitly trusted local executable (plus optional arguments). Do not copy either setting into Git. The adapter receives one JSON envelope on stdin and returns exactly event_id, digest, readback:true and indexed:true only after canonical note and index verification. Its stdout is machine data; no credentials. Retries reuse the exact original payload. Different content under the same identity is an error; use another sequence for a new event.
5. `python3 tools/engineering/lifecycle.py test` executes the governance suite and strict OpenSpec validation, recording actual success bound to the current payload digest. For product scope add actual applicable product test evidence to `evidence.product_tests`; CI/PR review must verify the actual product commands and artifacts as that capability is implemented. Existing product CI remains active. This bootstrap has no product changes and does not claim existing product tests pass.
6. Record the completion event with payload_digest from `digest`, then commit the work record and implementation. Run `python3 tools/engineering/lifecycle.py complete`, then push the current branch and open a PR. Pre-push runs the same trusted checks and Beads Dolt commit/pull/push. All intended tracked changes must be committed. Failure is an incomplete checkpoint, never an implicit waiver.
7. Record a private post-push decision event containing exact final SHA/PR and actual CI results, and update Beads. OpenSpec tasks are checked only after evidence; archive only after acceptance/review. The committed completion receipt covers payload contents excluding the work/receipt records, so a receipt-only commit does not invalidate evidence. The journal commit is the last real implementation commit when the event is created; a final private event supplies the resulting receipt commit SHA without a circular commit hash.

## Journal payload and trust

Required private fields: timestamp (ISO UTC), repo, stage, kind (start/decision/failure/blocked/complete), sequence, commit (real SHA), pr (URL or null), bead, spec, tests (actual results/artifacts), product_changes, lessons, decisions, next_step, payload_digest. Private delegation references may be added here only. Identity is a deterministic hash of repo/stage/kind/sequence. Content digest covers the canonical full private payload. Public receipts contain only schema, event_id, digest, state, kind, payload_digest. No private links or content.

The trusted connector integration is verified on the Mac host. Windows trusted adapters must choose an outbox under a user profile with owner-only ACLs; POSIX chmod does not establish Windows ACL privacy. Hosted Windows tests use temporary synthetic payloads and no private connector. Outbox entries are immutable private files persisted before delivery; adapter failure leaves no acknowledgement. Completion also checks private ack and original envelope digest. The actual local adapter uses the existing canonical connector, append-only event notes, readback and a journal index link; it serializes local index writes. Coordinate with external editors. A public receipt is not cryptographic proof of a wiki write. Public CI checks schema, source revision binding and linkage; only trusted completion verifies private acknowledgement. Anyone able to replace trusted local code/state has that trust authority; do not run PR-supplied adapters.

## CI and external contributors

`Engineering / checkpoint` runs on every PR, without path filters, with read-only contents, no private credentials, GitHub-hosted Ubuntu/Windows/macOS and pinned action SHAs. It repeats tests, strict specs, diff hygiene and public evidence/receipt validation even after `git commit --no-verify`. Fork PRs may omit journal receipts while providing linked stage/spec and test evidence. This reports pending journal and requires a maintainer to complete a trusted stage before acceptance. Do not invent a private receipt for a fork contributor. Public CI intentionally does not query Beads or the wiki; Beads IDs are validated structurally, and trusted completion verifies current status and sync.

A contributor must adapt `.engineering/work.json` and reference a maintainer-created Bead/change. For a future stage update base, stage, linkage and evidence; do not reuse the bootstrap identity. Reference upstream/source inputs by immutable commit. Coverage and GUI targets are future requirements, not fabricated measurements.

The workflow cannot be bypassed by a local hook flag. Preventing merge without it requires repository branch protection/rulesets and review of changes to gate code/workflows. API audit found both main branches unprotected. No protection changes are made by this bootstrap; owner must require the checkpoint and independent review. A malicious PR modifying its own check is a review/policy concern; this public workflow is not a sandboxed policy attestation.

## Scoped exceptions

Open a follow-up Bead and an OpenSpec delta where behavior changes. Record the exact affected check, file/revision scope, reason, risk, expiry UTC, actual failing evidence and owner approval in the PR; add a private decision event. Use a separate narrow reviewed policy change if the automated gate must be adjusted. Never globally disable hooks/tests, use a blanket environment bypass, or mark pending journal as verified. No exception permits secret disclosure or invented test results. Expired scope requires renewed review. Intermediate pending receipts are normal, not exceptions. Existing product baseline failures stay visible until separately fixed.
